# Coding and Engineering Quality

## Language and comments

- Write all source code, identifiers, user-facing strings, and code-related examples in English.
- Do not add code comments. Prefer clear names and simple structure; add a comment only when the user explicitly requests one.

## Quality and design

- Follow current, established best practices for the project's language, framework, and ecosystem.
- Prefer precise, complete changes that solve the root problem without unrelated refactoring.
- Keep code maintainable and scalable; use abstractions only when they make the solution clearer or easier to extend.
- Prioritize security, safe defaults, input validation, and explicit error handling.
- Preserve existing behavior unless a behavior change is required, and make intentional changes explicit.
- Follow the repository's existing conventions and reuse established helpers and patterns where appropriate.
